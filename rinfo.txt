1. INTRODUCTION & VISION
------------------------
NeuroExpense is a state-of-the-art personal finance management system designed for the modern user. In an era where 
digital transactions are constant and often untracked, NeuroExpense serves as a "Financial Command Center." The vision 
behind this project was to bridge the gap between complex enterprise accounting software (which is too hard for 
individuals) and simple note-taking apps (which lack intelligence).

The "Neuro" prefix signifies the application's focus on cognitive financial health—providing the user with the 
psychological feedback needed to spend wisely. By using visual cues like progress bars and color-coded alerts, 
the system trains the user to stay within their means.

2. PROBLEM STATEMENT & SOLUTION
--------------------------------
PROBLEM: Most people lose track of "micro-transactions"—small, recurring costs like coffee, subscriptions, or small 
online purchases. By the end of the month, these aggregate into a significant financial gap that is hard to explain.

SOLUTION: NeuroExpense provides a high-friction, high-reward environment for tracking. 
- HIGH-FRICTION: It encourages the user to manually log expenses, which creates awareness.
- HIGH-REWARD: It turns that data into beautiful charts and professional reports immediately, providing instant 
  gratification for financial discipline.

3. THE CORE TECH STACK (UNDER THE HOOD)
---------------------------------------
This project was built using a "Lean-Fullstack" approach, prioritizing performance and maintainability.

A. BACKEND (PYTHON / DJANGO 5.x)
   - Why Python? Its readability and powerful math libraries make it perfect for financial calculations.
   - Why Django? It provides built-in security (CSRF, XSS, SQL Injection protection) and an extremely fast 
     Object-Relational Mapper (ORM).
   - Middleware: Custom middleware handles session security and ensures only authenticated users can access data.

B. FRONTEND (HTML5 / VANILLA CSS / JAVASCRIPT)
   - Why No React/Vue? To minimize the "JavaScript Bundle Size." The app loads in milliseconds even on slow connections.
   - CSS Architecture: Built on a custom-designed "Glassmorphism" system using backdrop filters and HSL variables.
   - Interactivity: Vanilla JS handles the asynchronous behaviors, ensuring the UI remains snappy.
   - Visualization: Powered by Chart.js for smooth, animated rendering of financial data.

C. DATABASE (SQLITE3)
   - Why SQLite? It is serverless, requires zero configuration, and stores everything in a single portable file 
     (db.sqlite3). For individual users, it is faster than PostgreSQL or MySQL due to zero network latency.

D. REPORTING ENGINE
   - xhtml2pdf: Converts HTML/CSS templates directly into high-fidelity PDF documents.
   - ReportLab: Handles the complex layout logic for financial statements.
   - CSV Library: Standard Python library used for generating spreadsheet-compatible exports.

4. MODULE-BY-MODULE DEEP DIVE
-----------------------------

I. THE 'ACCOUNTS' MODULE
   This module handles the gateway to the application.
   - Models:
     - UserProfile: Extends the standard Django User model.
     - Fields: currency (USD, INR, EUR, etc.), dark_mode (Boolean), avatar (Image).
   - Logic: 
     - Uses 'Signals' (post_save). Whenever a new User is registered, a UserProfile is automatically created 
       via a background hook.
     - Handles login/logout redirects and session persistence.

II. THE 'EXPENSES' MODULE
   The heartbeat of the system.
   - Models:
     - Category: Stores the "Buckets" for spending (Food, Rent, etc.). Each category has an associated 'icon' 
       and 'color' (Hex code) for UI consistency.
     - Expense: The primary data record.
       - user (ForeignKey): Links the record to a specific person.
       - amount (Decimal): Precision-math field (12 digits total, 2 for decimals).
       - payment_method: Choices include UPI, Cash, Card, Bank, etc.
       - receipt: ImageField for storing photos of physical receipts.
     - Budget: The threshold engine.
       - month/year: Allows users to set different budgets for different months.
       - unique_together: Ensures a user can't create two budgets for the same category in the same month.

III. THE 'ANALYTICS' MODULE
   The "Brain" of the project. This doesn't have its own models but processes data from others.
   - Key Calculations:
     - Total This Month: Aggregates all expenses where the date is >= first of current month.
     - Average Daily: (Total Spent) / (Days Elapsed in current month).
     - Predicted Total: Projects the end-of-month total based on current spending habits.
     - Weekly Comparison: Calculates the percentage difference between this week and last week.

IV. THE 'REPORTS' MODULE
   The data export hub.
   - PDF Export: Uses a dedicated HTML template (`pdf_template.html`) styled for print. It loops through the 
     user's expenses and generates a structured table.
   - CSV Export: Streamlines data directly to the browser as a downloadable file.

V. THE 'CORE' MODULE
   The glue that holds the apps together.
   - Shared Templates: The `base.html` file containing the navigation bar and sidebar.
   - Landing Page: The initial "marketing" view for non-logged-in users.
   - Dashboard: The high-level summary view that users see after logging in.

5. DATABASE SCHEMA DICTIONARY
------------------------------

TABLE: auth_user (Django Default)
- id (INT): Primary Key
- username (VARCHAR): Unique identifier
- password (VARCHAR): Hashed string
- email (VARCHAR): User email

TABLE: accounts_userprofile
- id (INT): Primary Key
- user_id (INT): Link to auth_user
- currency (VARCHAR): 3-letter code (USD, INR, etc.)
- dark_mode (BOOL): UI preference
- avatar (IMAGE): Path to media file

TABLE: expenses_category
- id (INT): Primary Key
- name (VARCHAR): "Food", "Travel", etc.
- icon (VARCHAR): Lucide-icon name
- color (VARCHAR): Hex code (#3b82f6)

TABLE: expenses_expense
- id (INT): Primary Key
- user_id (INT): Link to auth_user
- title (VARCHAR): "Coffee"
- amount (DECIMAL): 150.00
- category_id (INT): Link to expenses_category
- date (DATE): When it happened
- payment_method (VARCHAR): "UPI", "CASH", etc.
- notes (TEXT): Optional details
- receipt (IMAGE): Path to receipt photo

TABLE: expenses_budget
- id (INT): Primary Key
- user_id (INT): Link to auth_user
- category_id (INT): Link to expenses_category
- amount (DECIMAL): Monthly limit
- month (INT): 1-12
- year (INT): e.g. 2024

6. FRONTEND DESIGN SYSTEM (AESTHETIC & UI)
------------------------------------------
The UI is built on a "Glassmorphism" design language, which creates a layered, translucent effect.

A. CSS VARIABLES (:root)
   The project uses a centralized color palette defined in `static/css/styles.css`:
   - --primary: #3b82f6 (Bright Blue)
   - --secondary: #1e293b (Dark Slate)
   - --accent: #f59e0b (Amber)
   - --glass-bg: rgba(255, 255, 255, 0.1) (Translucent White)
   - --glass-border: rgba(255, 255, 255, 0.2)

B. RESPONSIVE BREAKPOINTS
   - Mobile (< 640px): Sidebar collapses into a hamburger menu.
   - Tablet (640px - 1024px): Grid layout switches from 3 columns to 2.
   - Desktop (> 1024px): Full dashboard view with fixed sidebar.

C. ANIMATIONS
   - Hover Effects: Buttons use a subtle "Scale-up" (1.05x) and "Box-shadow" transition.
   - Chart Animations: Data bars grow from 0 to target value on page load (via Chart.js).
   - Page Transitions: Uses CSS opacity fades to ensure smooth navigation.

7. THE JOURNEY OF A TRANSACTION (STEP-BY-STEP)
-----------------------------------------------
1. USER ACTION: User clicks "Add Expense" on the dashboard.
2. FRONTEND: An HTML form is rendered, pre-populated with today's date and category dropdowns.
3. SUBMISSION: User enters data and clicks 'Save'. A CSRF (Cross-Site Request Forgery) token is attached for security.
4. ROUTING: The request hits `urls.py`, which maps it to `expenses:add_expense`.
5. VIEW LOGIC: 
   - `request.POST` is parsed.
   - Data is validated (checks for negative amounts, missing titles).
   - A new `Expense` object is created in the database via ORM.
6. SUCCESS SIGNAL: Django adds a "Success Message" to the message queue.
7. REDIRECTION: User is sent back to the expense list.
8. UPDATED UI: The charts in the sidebar automatically re-query the database and show the updated spending.

8. INSTALLATION & SETUP (THE "GET IT RUNNING" GUIDE)
----------------------------------------------------
Follow these exact commands to set up the project on any machine:

PHASE 1: PREREQUISITES
- Install Python 3.10 or higher.
- Install Git (if you want to clone).

PHASE 2: PROJECT CLONING & ENV
1. Create a folder: `mkdir NeuroExpense && cd NeuroExpense`
2. Create virtual environment: `python -m venv venv`
3. Activate environment:
   - Windows: `venv\Scripts\activate`
   - Mac/Linux: `source venv/bin/activate`

PHASE 3: INSTALLING PACKAGES
1. `pip install django`
2. `pip install pillow` (For images/receipts)
3. `pip install xhtml2pdf` (For reports)
4. `pip install reportlab`
5. `pip install django-crispy-forms` (If used)

PHASE 4: DATABASE SETUP
1. `python manage.py makemigrations`
2. `python manage.py migrate`
3. `python populate_categories.py` (Crucial: This adds the "buckets" like Food/Rent)

PHASE 5: LAUNCH
1. `python manage.py runserver`
2. Open Browser: http://127.0.0.1:8000/

9. DEVELOPER'S NOTES & DECISIONS
--------------------------------
- SECURITY: Every view that modifies data is wrapped in `@login_required`. This ensures that even if someone 
  knows the URL, they can't delete or add data without your password.
- PERFORMANCE: We used `select_related` in database queries. This is a Django trick that joins tables in SQL 
  level rather than Python level, making the list page 5x faster.
- SCALABILITY: While it uses SQLite, the code is "Database Agnostic." If you want to move to a production server, 
  you only need to change the `DATABASES` dictionary in `settings.py` to point to PostgreSQL.

10. COMPREHENSIVE FAQ
----------------------
Q: Where are the images stored?
A: In the `/media/` folder. Receipt photos go to `media/receipts/` and profile pictures to `media/avatars/`.

Q: How do I change the categories?
A: You can use the Django Admin panel at `/admin` (create a superuser first using `python manage.py createsuperuser`).

Q: Why doesn't the PDF look like the website?
A: PDFs use a simplified "Print Style" CSS. Browsers and PDF engines interpret things like `backdrop-filter` 
   differently, so we use a clean, professional design for the PDF exports.

Q: Is my data safe if I delete the project folder?
A: NO. The database is the `db.sqlite3` file inside the folder. Always backup this file!
